Conditions

Different actions based on different conditions

You already think in conditions

  • If it's raining, take an umbrella
  • If the password is correct, log in, otherwise show an error
  • If you're under 12, the ticket is free, else if you're a student, half price, else full price

Until now our code ran every line, top to bottom. Today some lines run only sometimes.

The if statement

const temperature = 28;

if (temperature > 25) {
  console.log("Go to the beach! 🏖");
}

console.log("This always runs");
  • The part in ( ) is the condition — a boolean expression
  • The code in { } is the block — runs only if the condition is true

Change temperature to 15 and run again.

else — the other path

const age = 14;

if (age >= 18) {
  console.log("Allowed");
} else {
  console.log("Denied");
}

Exactly one of the two blocks runs. Never both, never neither.

else if — more than two paths

const age = 14;

if (age < 13) {
  console.log("You are a child");
} else if (age < 20) {
  console.log("You are a teenager");
} else {
  console.log("You are an adult");
}
  • Checked top to bottom — the first true wins, the rest are skipped
  • else at the end is optional: the "none of the above" case

Combining conditions — logical operators

&&   AND → both must be true
||   OR  → at least one is true
!    NOT → flips true ↔ false
const age = 25;
const hasTicket = true;

if (age >= 18 && hasTicket) {
  console.log("Enjoy the concert");
}

if (!hasTicket) {
  console.log("Buy a ticket first");
}

Ranges need &&: age >= 13 && age < 20. You can't write 13 <= age < 20.

Truthy & falsy

if converts whatever is in ( ) to a boolean. These values become false: 

0    ""    null    undefined    NaN    false

Everything else is truthy — including "0", " " and -1. 

const name = "";

if (firstName) {
  console.log("Hello " + firstName);
} else {
  console.log("Please type your name");
}

Truthy or falsy?

Thumbs up 👍 for truthy, thumbs down 👎 for falsy:

  1. "hello"
  2. 0
  3. ""
  4. "0"
  5. -5
  6. undefined
  7. " "
  8. []

Check one with: if (value) { console.log("truthy") }

The ternary ? : — a short if/else

// long version
let message;
if (age >= 18) {
  message = "Adult";
} else {
  message = "Minor";
}

// short version
const message = age >= 18 ? "Adult" : "Minor";
//              condition ? if true : if false

Use it to choose a value. For running different code, use a normal if — it's easier to read.

You already use functions!

  • Values inside () are arguments — the input
  • Many functions give a value back: the return value — the output

Making our own function

// 1. Declare it (nothing happens yet!)
function sayHello() {
  console.log("Hello HYF 👋");
}

// 2. Call it — now it runs
sayHello();
sayHello();
sayHello();

If you never call a function, its code will never, ever, in a million years run.

Why bother?

  • Don't repeat yourself — write once, use many times
  • Give code a name — calculateTax() explains itself
  • Fix once — a bug fixed in the function is fixed everywhere
  • Small pieces — big programs are lots of small functions

Parameters & arguments

//              parameters (placeholders)
function greet(name, emoji) {
  console.log("Hello " + name + " " + emoji);
}

//     arguments (the real values)
greet("Ahmad", "👋");  // Hello Ahmad 👋
greet("Sana", "🎉");   // Hello Sana 🎉
  • Parameter = the variable name in the declaration
  • Argument = the value you pass in when calling
  • Matched by position: first argument → first parameter

Missing arguments & defaults

function greet(firstName) {
  console.log("Hello, " + callName);
}
greet(); // Hello undefined 😬

function greetNicely(callName = "friend") {
  console.log("Hello, " + callName);
}
greetNicely();         // Hello, friend
greetNicely("Peter");  // Hello, Peter

A parameter you don't pass is undefined — unless you give it a default.

return

The most important slide today

Return — the function gives a value back

function sum(a, b) {
  return a + b;
}

const result = sum(5, 10); // the call is replaced by 15
console.log(result);       // 15

console.log(sum(2, 3) * 2);        // 10
const total = sum(sum(1, 2), 4);   // 7

Think of the call sum(5, 10) as being replaced by the value it returns.

console.log ≠ return

Logs — shows it to you

function logDouble(n) {
  console.log(n * 2);
}

const x = logDouble(4);
// prints 8
console.log(x);
// undefined 😢

Returns — gives it to your code

function getDouble(n) {
  return n * 2;
}

const y = getDouble(4);
// prints nothing
console.log(y);
// 8 ✅

console.log is for humans. return is for the rest of the program. No return → the function returns undefined.

return also stops the function

function checkAge(age) {
  if (age >= 18) {
    return "Welcome";
  }
  return "Sorry, too young";
  console.log("I will never run");
}

console.log(checkAge(30)); // Welcome
console.log(checkAge(12)); // Sorry, too young

Once return runs, the function is done. Nothing after it inside the function runs.

Naming tells you what comes back

  • get… — returns a value: getTotalPrice()
  • calc… — calculates and returns: calcTax(price)
  • is… / has… — returns true/false: isEven(n)
  • log… / show… — prints something, returns nothing

One function = one job. If it's called getSomething, it must return something.

Predict the output

function a() {
  return 5;
}
function b() {
  console.log(5);
}
function c(n) {
  return n + 1;
  console.log("c ran");
}

const x = a();
const y = b();
const z = c(c(1));

console.log(x, y, z);
console.log(a() + c(10));

Scope

Where can I use this variable?

Global vs. local (function) scope

const bootcamp = "HYF";        // global — visible everywhere

function welcome() {
  const message = "Welcome to"; // local — only inside welcome
  console.log(message + " " + bootcamp); // ✅ both visible
}

welcome();
console.log(bootcamp);   // ✅ "HYF"
console.log(message);  // ❌ ReferenceError: message is not defined

Variables declared inside a function live and die inside it. Parameters are local too.

Block scope — { } is a wall

const age = 20;

if (age >= 18) {
  const status = "adult";
  console.log(status);  // ✅ "adult"
}

console.log(status);    // ❌ ReferenceError

let and const only exist inside the { } they were declared in — if blocks, loops, functions.

Need it outside? Declare it before the block with let.

Lexical scope — inner sees outer

const globalVar = "🌍 global";

function outer() {
  const outerVar = "📦 outer";

  function inner() {
    const innerVar = "🔒 inner";
    console.log(globalVar); // ✅
    console.log(outerVar);  // ✅ inner sees its parent
    console.log(innerVar);  // ✅
  }

  inner();
  console.log(innerVar);    // ❌ parent can't see child
}

outer();

You can look out through the window, but nobody can look in.

Same name, different variable

let name = "Global Gwen";

function sayName() {
  let name = "Local Lars"; // a NEW variable — "shadows" the outer one
  console.log(name);
}

sayName();         // Local Lars
console.log(name); // Global Gwen — untouched

Inside a function, the closest variable wins. Avoid reusing names — it confuses humans more than computers.

Anatomy of a for loop

for (let i = 0; i < 5; i++) {
  console.log("Round " + i);
}
let i = 0 begin — runs once, at the start
i < 5 condition — checked before every round; false → stop
{ … } body — the code to repeat
i++ step — runs after every round (i = i + 1)

Logs Round 0 … Round 4 — five rounds.

Step by step

for (let i = 0; i < 3; i++) {
  console.log(i);
}
i i < 3? body step
0 true logs 0 i → 1
1 true logs 1 i → 2
2 true logs 2 i → 3
3 false — stop —

⚠️ If the condition never becomes false → infinite loop. Close the tab / Ctrl+C in the terminal.

Building a result in a loop

function spam(number) {
  let repeated = "";                  // 1. start empty

  for (let i = 0; i < number; i++) {
    repeated = repeated + "hue";      // 2. add a bit each round
  }

  return repeated;                    // 3. return at the end
}

// Test cases: zero, one, many
console.log(spam(0) === "");
console.log(spam(1) === "hue");
console.log(spam(6) === "huehuehuehuehuehue");

Pattern: start value → update in the loop → return after the loop. Not inside the loop!

Looping over an array

const fruits = ["apple", "banana", "kiwi"];

// 0: apple

continue & break

continue — skip this round

for (let i = 1; i <= 6; i++) {
  if (i % 2 === 0) continue;
  console.log(i);
}
// 1 3 5

break — stop the loop

const names = ["Ali", "Bo", "Cy", "Di"];
for (let i = 0; i < names.length; i++) {
  if (names[i] === "Cy") {
    console.log("Found at " + i);
    break;
  }
}

Inside a function, return also stops the loop — and the whole function.
